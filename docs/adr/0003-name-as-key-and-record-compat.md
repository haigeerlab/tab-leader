# ADR-0003：`name` 原样用作锁名和存储 key，记录格式保持稳定

- 状态：已提议（随需求文档一起审批）
- 日期：2026-11-13

## 背景

很多项目在用本库之前已经有自研的多标签页实现。换成本库的那次发版里，旧代码的标签页和新代码的标签页会同时开着。如果两边用的锁名、存储 key 不同，它们互相看不见，就会各选一个 Leader，任务多跑一份。

## 决定

- `name` 原样用作 Web Locks 锁名，存储 key 为 `${name}:lease`、`${name}:alive`、`${name}:last`、`${name}:probe`，**不加库前缀**（需求文档 §3.5）。
- 租约 `{ tab, gen, exp }`、上次运行 `{ at, id }` 的格式视为公开契约，改格式属于破坏性变更。
- 新增的存活记录缺失时按「没停摆」处理（R6），不抢不写这条记录的旧实现。

## 备选方案

- **统一加 `tab-leader:` 前缀**：避免与业务 key 冲突，但迁移期新旧标签页互相看不见。

## 影响

- 避免与业务自己的 localStorage key 冲突，由调用方负责选一个不会冲突的 `name`；文档要提醒。
- 记录格式成为兼容性承诺，变更要走 ADR 和大版本。
